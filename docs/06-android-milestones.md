# 06 — Android 里程碑与验收

开发顺序：**先跑通通信（M1）→ 再跑通互通加密（M2）→ 再做 PQ（M3–M4）→ 再存储/UI（M5–M6）→ 最后发布（M7）**。

> M2 是整个项目最关键的验收点：如果 M2 失败，说明协议理解有误，必须在此停下修正，不要继续投入 M3。

## M0 — 工程骨架

**任务**
- [ ] Flutter 稳定版 + Android SDK/NDK 环境
- [ ] 建立 mono-repo 结构（见 01 文档 §6）
- [ ] fork `moxxmpp` 与 `omemo_dart` 至 `packages/`
- [ ] 添加 GPLv3 LICENSE、各文件来源标注规范
- [ ] GitHub Actions：`flutter analyze` + `flutter test` + `flutter build apk --debug`

**验收**
- `flutter run` 在 Android 真机启动空白页成功
- CI 全绿

## M1 — XMPP 通信基线（明文）

**任务**
- [ ] 连接、SASL SCRAM-SHA-256、资源绑定、断线重连
- [ ] roster 获取与展示
- [ ] 1:1 明文消息收发
- [x] XEP-0184 送达回执、XEP-0085 输入状态、XEP-0333 已读回执
- [x] MAM（XEP-0313）历史拉取（上线 catch-up + 会话内翻页，对齐 Conversations）
- [ ] Carbons（XEP-0280）
- [ ] SQLite（未加密）消息持久化
- [ ] 最小可用 UI：会话列表 + 聊天页

**验收**
- 两台真机（或两账号）互发明文消息，重启后历史仍在
- 与任意标准 XMPP 客户端互发明文消息成功

## M2 — 标准 OMEMO 互通（**关键验收**）

**任务**
- [ ] omemo_dart 集成：设备 ID 生成、device list、bundle 发布/获取
- [ ] X3DH 会话建立
- [ ] Double Ratchet 加密/解密
- [ ] OPK 消耗与补充
- [ ] 指纹计算与显示
- [ ] 信任管理：TOFU + BTBV
- [ ] EME（XEP-0380）声明与 `<body>` 降级
- [ ] 多设备（己方 2 台设备）同步

**验收**
- ✅ 与 **Conversations**（需支持 OMEMO 0.8 / `urn:xmpp:omemo:2`）双向加解密成功
- ✅ 或与 **Moxxy/Dino/Gajim** 中支持 0.8 的客户端互通
- ✅ 双方指纹一致
- ✅ 己方两台设备均能解密收到的消息（Carbons）
- ⚠️ 若测试对端只支持旧命名空间 `eu.siacs.conversations.axolotl`（0.3），需评估是否增加旧协议兼容层

## M3 — PQ 内核

**任务**
- [ ] liboqs NDK 交叉编译（`arm64-v8a`、`x86_64`）
- [ ] Dart FFI 封装：ML-KEM-768 keygen/encaps/decaps
- [ ] 纯 Dart 回退实现（`pqcrypto`）
- [ ] PQXDH 实现（见 02 文档 §3）
- [ ] B 轨设备列表/bundle 发布与获取
- [ ] 混合签名（Ed25519 + ML-DSA-65）
- [ ] 单元测试与向量测试

**验收**
- FFI 与纯 Dart 实现共享秘密一致
- 两个本客户端设备间建立 B 轨会话并加解密成功
- 首条消息体积统计符合预期且服务端接受

## M4 — 双轨协商与回退

**任务**
- [ ] `EncMode` 决策状态机（见 02 文档 §6）
- [ ] 能力缓存 + PEP 变更订阅
- [ ] 回退：混合设备场景整条走 A 轨
- [ ] UI 徽标（`🔒 OMEMO` / `🔒 PQ`）
- [ ] 加密信息页（两轨指纹、设备列表、信任状态）
- [ ] 失败重试与「无法解密」占位

**验收**
- 三设备场景（2 台本客户端 + 1 台标准客户端）中，消息对所有设备可解
- 移除标准客户端后，自动升级为 B 轨
- 无任何场景下发送对端无法解密的消息
